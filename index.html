SkinSync

Android app and research paper · Team of four with a faculty mentor

Helps people with acne-prone skin choose base makeup that suits them. It analyzes a face photo and a short quiz for skin tone, skin type, and acne severity, then reads product labels with OCR and scores each product. My part: the Python backend and the technical documentation of the algorithms.

How it works

Skin tone is measured in CIELAB, mapped to Fitzpatrick types, and cross-checked by a trained classifier. Skin type blends texture features with an eight-question quiz at 70/30, weighing the quiz more because habits proved steadier than one image (84% accuracy). Tesseract OCR and fuzzy ingredient matching feed a 0 to 100 compatibility score. I tightened face validation so non-face images are rejected.

Limits
  • Skin type is the hardest task at 84%, and Dry skin is often mistaken for Combination.
  • OCR struggles with curved, shiny, or small-print packaging.
  • Ingredient results depend on the database, which needs regular updates, and errors cluster near verdict thresholds.
  • It needs good image quality and a network connection.
  • It is not a medical tool, and the ratings come from 50 purposely selected participants.

How it works

Timers are calculated from timestamps, never counted, so refreshing or sleep cannot make them drift. Warnings tick from a Web Worker because browsers slow timers in hidden tabs. You label each tab switch or idle period as Productive, Necessary, or Distraction, and breaks are declared by you and never tracked. ColrFilm

Chrome extension · Manifest V3 · Python and JavaScript

Corrects colors in real time for people with color vision deficiencies. It filters web pages, images, and HTML5 video with GPU-composited SVG and CSS filters, with no screenshots, screen recording, or frame extraction. It runs fully locally, with no backend, account, or analytics.

How it works

Python owns all the color math: simulation models (Machado 2009, Brettel 1997, Viénot 1999) and Fidaner-style daltonization, which reduces to a fixed 3×3 matrix. The coefficients are exported to JSON, and a JavaScript engine turns them into SVG color-matrix filters, so correction runs in the browser compositor. It has 129 automated tests (70 Python and 59 JavaScript), including checks that JavaScript output matches the Python results. Selective filtering skips text and background pairs that are already distinguishable, and settings persist in chrome.storage.local.

Limits
  • An assistive tool, not a cure for color blindness.
  • One fixed matrix per profile and intensity, so it cannot adapt to the specific colors in a scene.
  • Tritanomaly gives only a small separation gain and looks unnatural at high intensity.
  • Saturated colors clip at strong settings.
  • More advanced image-dependent algorithms were studied but cannot be used, because they would need frame access.
Results

Measured: the JavaScript engine applies a filter to 1,000 elements in about 0.18 ms on average, and the Python color math takes about 13 to 14 ms for a 256×256 image. Python and JavaScript agree on corrected colors within 1e-4. Findings I recorded: saturated colors clip at high intensity, protanomaly needs full strength for a clear gain, and tritanomaly gains are limited. Ratings: a sample dataset of 20 responses, not collected from real participants, averaged 4.48 out of 5, with reliability at 4.50. Color distortion was the weakest point. It is not evidence of real-world effectiveness, and testing with real participants is the next step.

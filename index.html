SkinSync

Android app and research paper. Team of four students with a faculty mentor.

SkinSync helps people with acne-prone skin choose base makeup that suits them. It analyzes a face photo and a short quiz to find skin tone, skin type, and acne severity, then reads a product’s ingredient label with OCR and scores how well the product fits that skin. My part was the Python backend and the technical documentation of the algorithms.

  • Skin tone: 94.53% accuracy on 1,500 samplesLightness is measured in the CIELAB color space with outliers trimmed, mapped to Fitzpatrick types, and cross-checked against a trained classifier.
  • Skin type: 84% accuracy, quiz and image combinedTexture features from the photo are blended with an eight-question quiz at 70/30. The quiz gets the heavier weight because habits like how quickly skin gets oily proved more stable than a single image.
  • Acne: 96% category accuracy, 89% severity accuracyLesions are found with color and shape rules inside the detected skin area, then graded by a trained classifier that is cross-checked against lesion count.
  • Ingredient matching: 94% accuracy on 500 test casesTesseract OCR reads the label, then exact and fuzzy matching find each ingredient in an INCI database. Points for good and bad ingredients become a 0 to 100 score and a verdict.
  • User rating: 4.42 out of 5 from 50 respondentsTesters rated the app on ISO 25010 quality criteria. Usability scored highest at 4.53.
Problem I debugged

Non-face images were passing validation because the face detection threshold was too permissive. I tightened it and added explicit rejection rules for text-heavy images. While testing, I also found a reference hash with 65 characters instead of 64, which broke exact matching.

Documentation

I wrote the technical report chapter that explains the skin tone and skin type pipelines step by step with pseudocode. The team also wrote an ACM-format research paper covering the full system and its evaluation.

Deployment

The Python backend runs on Google Cloud Run, and the mobile front end is built with Flutter.

Limitations we reported

Skin type was the hardest task, mostly telling Dry skin from Combination. OCR struggles with curved or small-font packaging. The app helps with product choice and is not a medical diagnosis tool.

NoCrast

Web app. Everything stays in the browser, with no server or account. Ongoing project that I’m still developing.

NoCrast tracks how long your tasks take, notices when you wander off, and shows you your own habits. Each task has a timer, deadline warnings arrive as desktop notifications, and tab switches and inactivity are logged but never judged without your say.

  • Timers that cannot driftThere is no stored counter. Task time is calculated from the clock each time, so refreshing, sleep, and background throttling never make it wrong.
  • Warnings that work in background tabsBrowsers slow timers in hidden tabs, so the warnings tick from a Web Worker clock instead. Each task gets up to 14 warnings, from one month before the deadline to overdue.
  • Distraction tracking you controlYou label each tab switch or idle period as Productive, Necessary, or Distraction, and only unlabeled and Distraction events count. Breaks are declared by you and are never tracked.
  • Private by designData lives in the browser using IndexedDB. Exports are validated before an import replaces anything, and analytics say “not enough data” rather than invent a number.
  • Tested and audited68 unit and component tests plus 16 browser tests in real Chromium all pass. Lighthouse gives 100 for accessibility, best practices, and SEO, and 94 to 100 for performance.
How it’s built

The app is about 1,900 lines of TypeScript in 39 files, with 5 runtime dependencies and a 112 KB gzipped main script. The code has three layers. Pure utility functions hold the rules, such as timer math and break math, so they are easy to test. Services handle storage and browser features. React components only display the data. Browser tests use a fake clock, so a 30-day warning schedule is checked in seconds. GitHub Actions runs the typecheck, lint, tests, and build on every push.

Limitations I documented

A web page can only see its own tab, so NoCrast knows when you leave but never where you went. Notifications need the tab to stay open and do not work on most phone browsers. Tests ran in Chromium only, and a manual check is still needed to confirm the operating system shows the notifications.
